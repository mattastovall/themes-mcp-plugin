# Review evidence and delivery

Review cards show shot label, selected asset, start/duration, narration line, set/station, framing, agent judgment, user decision and proposed fix. Compare continuity pairs beside their masters. Keep previous versions available with explicit version labels.

Assess narration sync and visual craft separately. Grade A (works), B (minor improvement), C (visible issue), or n/a, with the concrete observation. A grade is never approval. Each fix is no change, edit-only, or new generation, with an estimate where applicable. Validate observations against the correct source revision; inspect transitions across several frames and measure suspected overlay collisions. Do not extend narration-locked shots without accounting for their line timing.

Track quoted, reserved, settled and uncertain costs separately. Totals need currency and scope; unknown settlement must remain visible. Provider price examples from an earlier project are not a current quote.

Verification records identify the output and version, check, method, result, timestamp and limitations. Check dimensions, duration, frame rate, decoding, audio presence, loudness/peaks, text/framing, transitions and last frame. Sampled frames do not prove full motion or sound. Opening an editable source with dependencies is a separate check. Export success is not creative acceptance or legal approval.

## Handoff template

- Project key, thread ID, explicit sequence ID, board/source revision and review URL
- Current stage and selected candidates by shot key
- Script/line table and pinned voice takes
- Cast, set masters, camera plan and continuity decisions
- Generation requests, models/settings, reference identities and uncertain outcomes
- Exact editable source to open, application/version and asset dependencies
- Current cut version; requested and measured output properties
- User decisions with their source revision; outstanding changes
- Spend summary and missing settlement evidence
- Checks performed, failures, unverified items and next steps

Store narrative notes in thread Markdown with version checks. Structured server records remain authoritative for candidate selection, approvals and spend.

## Optional local export profile

For new local productions use artifacts/ (raw, generated, intermediate, proxies), working/ (editable draft, review exports and README.md), and final/ (completed delivery exports). Preserve existing paths and original supplied names where relinking or provenance would be harmed.

Names: <project-key>_<type>_<item>_<stage>[_<variant>][_<ratio>][_<size>][_<duration>]_v###.<ext>. Use lowercase hyphenated fields, stable project keys and numbered shots. Final visual exports include measured size; final video/animation also includes actual duration. Carry the draft version into review and final outputs. Keep source-to-export mappings.

Client naming overrides are explicit project settings. Do not embed one customer's sheet, local path, end card, caption font or aspect treatment as a global default. Registering assets in an external tracker or publishing a board requires authority for that action.
